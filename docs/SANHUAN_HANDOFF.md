更新：2026-10-29。先读 EXECUTION_GUIDELINES.md。本文件描述本轮代码，历史通用原脚本诊断不能替代这里的流程回归。

## 当前代码

- `scripts/legacy/modules/dungeon_flow.lua`：公共阶段执行器。按检查任务、接取、队伍、入场、战斗、离场、交付顺序推进；轮数与等待时间有界。核对任务 ID，允许从已有任务/副本内继续。交付前要求任务完成，交付后要求记录消失并已离场，再发成功回执。
- `scripts/legacy/modules/dungeon_api.lua`：集中实现任务读数、NPC 选项、可见且可用的按钮事件、背包空位、队长状态、战斗调用及巡点。采用实际游戏接口；不导入原通用宿主的占位函数或混合框架环境。
- `scripts/legacy/modules/sanhuan.lua`：两个独立副本定义。老三环读取三才峡谷面板；新三环读取任务描述里的目标坐标，允许显式配置巡点/离场参数。
- `scripts/legacy/dungeons/sanhuan_old.lua`、`sanhuan_new.lua`：任务入口。
- `scripts/legacy/manifest.json` 与 `design/task-catalog.json`：老任务 ID `dungeon_00320005` 保留，入口切换到新明文流程；新增 `dungeon_new_sanhuan`。两项采用 `dungeon_flow_v1` 完成契约，使用角色技能页与现有通用战斗维护。

这两项执行明文重构规则，`rules_modified=true`，没有宣称保持原字节码。原规则仍保存在原库中，供静态核对。

## 老三环已实现的流程

苏州钱宏宇 (133,260) 接取“除匪首力破三关”，队长等待至少三人后选择原规则入口；队员等待入场。场景 653 / 三才峡谷内，以实际任务和 Sancai 面板推进：宋兵、副都统、匪类、都统、余毒、野熊、红熊王、葛荣。原路线点来自 `00320005.listing.txt`。面板已满时等待下一页或任务状态，不继续按旧页攻击。

完成任务变量后，到宋兵接应人 (63,196) 选择离场，返回钱宏宇交付。满包、状态不可读、任务身份变化、取消坐骑未适配、等待/战斗超时均有具体退出原因。没有以背包里已有物品判断任务完成。原本地面包裹拾取及特殊 Boss 机制没有新增实现。

## 新三环已实现与待补资料

新三环名称“剑荡三环除妖魔”，入口采用用户提供的楼兰何悦 (295,68)。[官方合并副本说明](https://event.changyou.com/xtl/201504/qingmang/index.shtml) 对应炎魔山及王阎、洪棘妖王、火焰妖魔。该网页是历史说明，只作名称和玩法来源；当前客户端细节优先看本机和用户测试。

已实现：读取自身任务记录、接取、队长/队员分工、按实际入场场景创建战斗上下文、任务目标坐标导航、任务完成后的返回坐标或指定 NPC 离场、交付与完成回执。代码不套用老三环场景号。

尚未取得当前版本的固定巡点路线、多级入场对话及离场 NPC/选项。默认优先使用任务记录下发的坐标；没有当前场景目标坐标且没有可攻击目标时，15 秒后明确报告缺少巡点配置。可在参数中填写 `100,120;110,130|150,180`；分号分点，竖线分组，每组最多 24 点、最多三组，所有组按顺序巡点，组不冒充游戏战斗阶段。离场 NPC 与离场选项必须同时填写或同时留空。填写 NPC 时要求当前对象列表内唯一同名 NPC；留空时只使用任务描述里楼兰何悦的返回坐标。

## 坐骑接口的具体缺口

本机已确认 `GetMountID` 以及 `DispelBuffByIndex` 注册。`Player:DispelBuffByName` 是参考程序封装，不是本机游戏可直接调用的方法。按索引取消 Buff 的接口已定位，但“坐骑 Buff → 正确取消索引”尚未实现。不能根据函数名猜测 `LuaCancelRide` 的参数，也不能把显示 tooltip 的方法当成读取 Buff 名称。

已将检查提前到接取/入场之前；已下坐骑继续。若已有取消接口返回提交成功，等待实际 MountID 变成 -1，最多八秒，不重复提交。当前版本缺少取消接口时直接提示先下坐骑，不进入副本后才报错。后续应补齐准确的 Buff 数据/索引读取及取消回执，再去掉这个人工前置条件。
