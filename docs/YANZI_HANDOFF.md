# 燕子坞完整战斗流程

更新：2026-10-31。入口 `yanzi`，执行/结果契约 `yanzi_flow_v1`。沿用游戏内驻留 Lua 5.4，通过游戏 LuaPlus 5.0 API 与已核对的原生内存布局运行。采用独立明文规则，不加载原程序混合通用宿主；原规则用于核对流程、坐标、选项和机制。

## 已完成

1. 准备与入场：读取活动页“讨伐燕子坞”当日次数，核对背包空位、角色战斗配置、实际队长、队员同场景及集合位置。通过现有寻路接口前往太湖李纲 (70,120)，选择普通/初级/中级/高级，等待实际进入场景 236。
2. 呼延豹 (79,203)：队长选择“战斗吧！”，优先段延庆，再清岳老三、云中鹤；核对实际目标身份、血量变化及新阶段提示。离开本战场前取得悲酥清风解药。
3. 钱宏宇 (217,150)：队长开场，阻截援军、巡点及优先鸠摩智；读取本轮新出现的 1–9 拨提示。保护钱宏宇，观察到存活后连续两次死亡即停止。没有目标时等待/巡点，不把空场当作通关。
4. 华赫艮 (180,88)：等待“从地道进入燕子坞”，提交后以实际内场坐标确认转场。鸠摩智仍在时先处理，不跳过首领。
5. 慕容复：队长集合并引怪，队员等待；按配置决定是否先打王语嫣。首次输出后等待实际生命/反伤反馈，避免攻击动画未结束就取消或重复输出。斗转星移选择自己停手、收珍兽；冰天雪地按当前提示坐标避让并保持停手 5 秒；悲酥清风使用解药并等待对应 Buff 消失。机制期间继续人物治疗，恢复同一珍兽的实际出战状态后再输出。
6. 离场与结果：确认本轮慕容复死亡，可选拾取附近包裹，经出口回太湖，刷新并核对活动次数恰好增加一轮；随后输出 `done`，顺序队列才进入下一项。次数已满时输出 `already_done`。支持多轮、外场/钱宏宇/慕容复战斗区域的途中接续、队员和峨嵋只治疗。

后缀核对：普通无后缀；初级 `·闻恶`、中级 `·识恶`、高级 `·罚恶`。遇到其他难度后缀停止，不混用对象。旧历史提示不推进新一轮；对象消失不单独记作死亡。

## 配置与使用前提

|配置|默认/范围|用途|
|---|---|---|
|副本难度|普通、初级、中级、高级|入场选项与首领后缀|
|队伍人数|3；3–6|入场及开场集合要求|
|轮数|1；1–20|完成后接续下一轮|
|状态等待/秒|45；5–180|集合、入场、对话和转场等待|

|攻击王语嫣|关闭|慕容复机制空档先处理王语嫣|
|自动获取并使用副本解药|开启|段延庆后取得解药；中毒时使用|
|结束后请求拾取附近包裹|开启|结束战斗后打开附近包裹并领取一次|

人物输出、宠物技能、恢复与峨嵋策略沿用角色“技能”页。需已组队、已下坐骑；不包含自动组队和死亡复活。跨地图前往太湖沿用现有通用寻路/已有传送规划，不新增未经核对的城市 NPC 资料。当前确切限制见 FIX_CHECKLIST.md。

旧队列快照没有这批必要参数时会明确要求重新添加燕子坞节点；旧角色草稿空难度迁移为普通，旧 `xzk119` 映射到攻击王语嫣。界面不再显示原始不明用途输入框。主任务 ID 不变。

## 本批原生接口

- `loot_snapshot`：单独读取 `CTripperObject_ItemBox`，虚表 RVA `0xc3fc28`，双 ID +0x28/+0x2c，XZ +0x4c/+0x54、移除标记 +0x48。复用有界树校验，最多 512 对象、64 待查节点、8 ms 读数预算。不会把包裹混入原有玩家/陷阱快照。
- `open_loot(client:server)`：重读当前包裹身份、未移除状态和距离（不超过 4）；核对 `CGameInterface` 实例 `0x105d608`、虚表 `0xb277a8`、虚槽 +0x110 指向当前函数 `0x226e80`，提交 `OpenPackage(client,true)`。不接受调用方传入地址。沿用现有版本/世界状态检查，场景变化停止。
- 拾取顺序：选起点半径 35 内最近包裹 → 靠近 → 关闭旧 LootPacket 并确认 → 打开本包裹一次 → 等新窗口可见 → 再查背包空位 → `PlayerPackage:PickAllItem()` 一次。窗口没有反馈时不重复打开/领取；被队友取走的包裹跳过。最多 16 个包裹、总计 60 秒。领取请求不是成功回执；解药/宝箱调用方另查实际物品变化，副本完成只用战斗、离场及活动次数。
- 解药来源：背包已有解药可用于本场（不作为副本完成凭据）；段延庆地面包裹、最多 3 个副本宝箱及临时背包。临时背包使用 `Bank:GetTemBankItemNum/EnumTemItem` 和实际动作控件。物品使用前复查槽位、定义 ID、名称和数量，提交后等物品/Buff 反馈；无反馈停止。
- 首次攻击计数只在原生执行返回 1 时增加；冷却或不可执行不计数。珍兽收回回执与机制结束同时出现时，先恢复出战并核对，再解除输出等待。

没有增加 DLL、驻留线程或安装文件。游戏当前 SHA256 为 `72f4898ee04d2e8a6d94ff6d45cdc183dfa655eae40c31ddc67dcc2099d9c00d`。
