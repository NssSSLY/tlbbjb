# 四绝庄执行交接

更新：2026-10-31。本批补齐四绝庄的四档难度、队友间距/分担失明、陷阱枚举与绕行、机制珍兽休息及恢复。沿用上一批完整明文流程；真实游戏由用户测试。未生成安装器、ZIP 或更新安装目录。

## 当前入口与流程

任务 ID `sijue` 保留，生产入口为 `scripts/legacy/dungeons/sijue.lua`，规则为 `modules/sijue.lua`，公共接口为 `dungeon_api`，完成契约 `sijue_flow_v1`。不再为本任务加载原通用宿主、原字节码或第三方 DLL。原规则仅作静态依据，仍保存在原库。

1. 读任务，检查实际技能、背包空位及下坐骑状态。新任务由队长在苏州潘菁菁 (195,215) 接取；检查队伍人数及同场景，队员只接受对应的共享提示。
2. 按所选普通/初级/中级/高级的实际选项进入四绝庄，确认场景 291。任务名同时匹配原字典键和游戏本地化名称；首领接受该模式后缀及原基础名称，其他模式后缀报错。
3. 闵墨：按敲钟分工选定四绝钟；其他角色不会被后备选敌逻辑再次分配敲钟。护卫、教头及首领使用角色技能页的通用战斗。
4. 秦韵：有烛影摇红时，在原候选线 x=16..40、y=114 中选择离其他玩家至少 6 坐标单位且未被陷阱覆盖的近点；没有可用点则停手等待。回音幡仍从两处候选点避让，可选对角路线。启用“本角色分担失明”时，优先处理自身烛影摇红/回音幡，确认同队成员双 ID 及实际位置仍在秦韵场后，到 (43,104) 停手待命、继续治疗；队友在其他场地时退出待命，阶段完成仍由任务/首领状态判断。
5. 陶青：先清青鹰和四系墨虎；有青鹰的守护/天罡护体时等待对应目标，不继续对护体首领输出。
6. 庞企：先处理星罗武士；读取原规则龙柱提示 73–77，按原坐标引导；提示缓存有 8 秒有效期，不因同一条提示持续显示而无限续期。
7. 首领同一身份的零生命需连续确认；原规则明确使用的同名友方 NPC 形态也需连续两次相同身份读数。目标消失不记击杀；后续首领的实际出现可作为队友推进/接续的独立证据。
8. 各场结束到潘菁菁的原坐标选择实际转场选项；最终要求任务变量 0 为完成，选择离场选项，确认回苏州，再交付任务。记录消失且在苏州后发回执，顺序队列才进入下一项。

支持副本内接续、已完成待交付、多轮、队长/队员、峨嵋只治疗。等待中继续调用公共恢复维护；只治疗角色不提交人物输出。

所有场内移动和接近转场 NPC 接入陷阱规划器；整条直线路径和各段绕行都检查圆形避让范围。自身处在陷阱内时优先撤离；目标被陷阱覆盖时停手等待，不让基础攻击自动追进危险范围。位置/陷阱变化时重规划，原地无进展及总战斗时间均有限制。

机制停手选择并核对自身目标，暂停本执行层输出；出战珍兽用游戏原生“休息动作”收回。机制结束只恢复脚本收回的同一槽位/GUID 珍兽。指令提交后读取实际出战状态，不确认不重发。人工更换/出战/收回、身份变化会停止，不覆盖人的选择。战斗维护识别脚本暂停状态，停止珍兽技能、回气和喂养，继续人物治疗；待确认的珍兽动作先等待反馈，再收回。

## 参数与运行前提

- 难度下拉提供“普通、初级、中级、高级”，对应入场键 `SJZ_100129_11`、`XKFB_250115_04`、`XKFB_250115_47`、`XKFB_250115_05`，后缀为空、`·闻恶`、`·识恶`、`·罚恶`。
- 队伍人数 3–6、轮数 1–20、状态等待 5–180 秒、每轮战斗上限 30–3600 秒。
- 敲钟分工为“队长 / 本角色 / 其他队友”，默认队长；秦韵对角避让、庞企龙柱引导及本角色分担失明为独立开关。分担失明只由分配到的角色开启，默认关闭。
- 陷阱避让距离 2–10 游戏坐标，默认 4。这是规划净距，不冒充游戏提供的真实伤害半径；规划器不包含游戏碰撞网格，实际移动仍由游戏寻路执行。
- 使用角色技能页配置，不新增逐副本技能副本。旧参数草稿的相应开关可迁移；旧队列缺少本批必要参数时要求重新添加本项。
- 当前公共坐骑取消接口缺口保留，需先下坐骑；已组队后运行。没有增加死亡复活、自动组队或掉落拾取。
- 修改了原生引擎，后续部署需使用本轮同一套 `TLBB.exe`、`TLBBEngine.dll`、`TLBBData.rcc`。只复制 Lua 到旧安装目录不能补上 Buff 与机制对象读取。旧队列缺少分担/陷阱参数时重新添加本任务。

## Buff 与静态依据

新增只读宿主 `object_buff_ids`，输入经过验证的 client/server 双 ID（自身为 -1:-1），不接受任意地址。当前 Game.exe 静态代码确认对象 +0x180 为 Buff 树、+0x188 为数量，节点 +0x20 为状态 ID。限定 256 个状态、512 个对象、32 层身份查找及 8 ms 原生读数预算；树循环、重复 ID、身份变化和读取失败都报错。

Lua 层通过游戏 `Lua_GetBuffInfo(id)` 的第二个结果取得名称，每次最多 8 个。空定义、数量不符保持未知错误。对象 ID 使用整数格式序列化，避免 Lua 数值的 `.0` 与原生解析不一致。未增加 DLL 或驻留线程。

证据在 `artifacts/sijue-2026-10-30/native-contract.json` 及同目录反汇编/指令表。特别注意原 DLL 的 Lua 注册顺序：`CEnumObjBuff` 实际回调为 0x180126fa0，0x1801277b0 属于下一项 `GetMiJiSkillIndex`；不要复用早先候选推断。龙柱格式化指令为 i+2，实际提示键是 73–77。

## 本批接口依据和性能上限

`mechanism_snapshot` 只读枚举当前已校验的 `CObject_PlayerOther` 和 `CObject_Special`，保持战斗目标枚举仅支持 NPC；不把玩家或陷阱放进通用选敌。主虚表 RVA 分别为 `0xc3b978` / `0xc3f498`，自身 `0xc37f28`。公共坐标 +0x4c / +0x54，双 ID +0x28 / +0x2c。校验管理器、树计数/循环/哨兵、对象身份、移除标记与有限坐标，并在读后复查身份。最多 512 对象、64 待查树节点、8 ms 原生读数预算；不增加 DLL 或驻留线程。

`dungeon_navigation` 只规划陷阱净距，最多 32 个陷阱、4096 网格、32768 待选项，每 64 次展开让出执行；缓存路径并在陷阱或实际位置变化时复查下一段。游戏自动寻路没有反馈时按等待时限退出，不宣称无条件不会卡顿。

珍兽调用当前 Game.exe 的 `Pet:GetPetRelaxAction()` / `GetPetFightAction()` 动作对象，经 `GetID`、`IsEnable` 和 `IsCanDoAction` 检查后使用已有动作按钮，恢复旧按钮值。`Pet:GetAIType` 是珍兽性格信息，不用它冒充停手控制。休息/出战状态最多等待 8 秒。

静态记录在 `artifacts/sijue-mechanisms-2026-10-30/`：`object-vtables.json`、`pet-api-registration.json`、`pet-relax-action.asm.txt`、`pet.listing.txt`；参考 `180133810.cpp` 验证特殊对象分类和公共坐标。没有执行第三方 DLL 或在线游戏动作。
