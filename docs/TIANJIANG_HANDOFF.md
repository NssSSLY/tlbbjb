# 天降奇兽流程

更新：2026-11-06。入口 `dungeon_002eb7bd`，执行 / 结果契约 `tianjiang_flow_v1`，代码在 `scripts/legacy/dungeons/tianjiang.lua` 与 `scripts/legacy/modules/tianjiang.lua`。独立明文规则，不加载原程序通用宿主；规则对照 `原脚本源码/Script64/副本/天降奇兽(刷丹).lua`。离线测试通过，未实机验证。

## 已完成

1. 活动时段：按服务器时间判断 13:30–14:00、18:30–18:50、19:00–19:30、21:45–22:15。不在时段内时，没完成过轮次就停止并写明。
2. 找奇兽：队长请求组队跟随，沿楼兰（场景 246）路线巡查，前两个时段和后两个时段各一条。遇到友好 NPC 逐个对话，对话里有脚本 808121 选项的就是千年奇兽，日志写明它的名字。队员到 (173,156) 等待。
3. 入场：点那个选项一次，最多等 60 秒，不重发。
4. 副本（场景 268）：队长在 4 个点之间巡逻，打护岛神兽和无敌飞天猫。队员打可见目标，否则跟到队长 4 码内。
5. 离场：两个目标都死亡或进场满 10 分钟后，拾取一次（可关），在 (70,67) 和 (76,70) 之间走动，最多 2 分钟。
6. 结果：离开场景算完成一轮，继续下一轮，直到时段结束或达到最多轮数。原脚本没有活动次数检查，这里也没有。

## 配置

|配置|默认 / 范围|用途|
|---|---|---|
|最多轮数|20；1–20|时段结束也会提前结束|
|状态等待 / 秒|45；5–180|状态等待|
|找不到就结束 `tianjiang_search_minutes`|30；1–120|原 `bjk166`|
|拾取 `tianjiang_loot`|开|结束时拾取|

旧队列缺少这些参数时会要求重新添加本项。

## 与原规则不同的地方

|原规则|现在的做法|可能的偏差|
|---|---|---|
|定时抢点（`DoSystem`、`SP_OpenTalkAndClickedOption` 高频发包）|**不移植**。你说过抢购类不做，这也是同类做法|活动刚开始时可能抢不过别人|
|自定义抢点坐标 `bjk19` 等 4 项|随抢点一起去掉|—|
|自定义路线文件“坐标天降奇兽”|未移植，用脚本内置路线|—|
|按称号“千年奇兽”找|读不到称号，按对话里的脚本号识别|要多问几个 NPC|
|`CallFun(12, id, 808121, 1)` 直接发包|打开对话，点脚本号对应的选项|如果选项不显示，会一直找不到|
|`bjk166` 默认 0|默认 30 分钟|原默认值会立刻结束|

## 需要实测确认

- **脚本号读取：** `DataPool:GetNPCEventList_Item` 第 3 个返回值是否就是 808121，这是最关键的一点。
- **服务器时间：** `os.date('*t', DataPool:GetCurrentServerTime())` 在游戏内的结果。
- **出口：** 原脚本在这两个点之间走动离场，没有更多说明。
