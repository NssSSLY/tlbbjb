# 战斗维护 0.13.0

日期：2026-10-25。仅修改源码、编译开发版、执行自建窗口与官方 Lua SDK 验证。未操作真实游戏，未生成安装包、ZIP 或新的发布目录。

## 本批制作方式

原棋局主流程 scripts/legacy/original/qiju.lua 继续直接执行原 605 条 Lua 5.4 指令。本批新增 modules/battle_support.lua 是本程序的宿主适配，不是把原 CEnumSkill、原注入 DLL 或整个原技能模块直接搬过来。原字节码与公共过滤函数的来源验证继续保留。

原 common.lua 的 g_MenPaiInfo 和 player.lua 的 Player.GetRage 已静态核对：0–8 为少林、明教、丐帮、武当、峨嵋、星宿、天龙、天山、逍遥；9 为无门派；10–15 为慕容、唐门、鬼谷、桃花岛、绝情谷、恶人谷。桃花岛的资源键为 ENG，其他已知门派为 RAGE。昆仑在官网当前资料站中列出，但所提供原规则没有其编号，暂不猜测；未知编号原样显示，技能枚举不依赖名称映射。证据：artifacts/battle-maintenance-0.13.0/school-reference.json。

官网参考：[门派资料目录](https://tl.changyou.com/data/index.shtml)、[珍兽获得与培养](https://tl.changyou.com/data/bbs/hdypy.shtml)、[珍兽属性](https://tl.changyou.com/data/bbs/zssx.shtml)。这些资料用于区分玩法与技能类型，实际已学动作及当前可用性仍从用户的本机客户端读取，不以网页列表代替角色状态。

## 界面与配置

“技能”页新增：状态 / 已学技能、输出技能、人物恢复、自身增益、珍兽策略。目标规则页仍标为待适配。

读取按钮执行独立、只读的 battle_inspect 任务；其他任务运行中禁用。显示人物生命及上限、气量及上限、怒气 / 门派能量、门派编号，以及出战珍兽名称、生命、上限、快乐度。列表显示已学动作、动作 ID、游戏判定的可用状态、冷却原值和已知限制。选中动作后可以加入指定用途。列表是一次读取；战斗运行时每秒更新状态及已参与检查的技能。任务停止后保留最近读数，不伪装成持续刷新。

人物和珍兽的技能用途必须分别配置。人物恢复、自身增益、珍兽维护默认关闭，空输出列表沿用基础攻击。每组最多 12 个名称、600 字符，单名最多 47 字符。恢复与珍兽阈值 1–95%，自身增益最小间隔 10–600 秒。若开启珍兽喂养，其阈值必须大于珍兽生命停止阈值。

战斗维护配置存储在当前角色 battle 中。流程启动时将恢复、珍兽规则冻结为本次流程的 battle_system；运行中修改不会改变正在执行的快照。每个节点的显式输出技能仍是独立参数。批量复制任务时保留目标角色的技能与珍兽绑定，防止将其他门派的名称直接用于本角色。

## 执行逻辑

- 依据 GetActionNum('skill') 读取实际动作槽，上限 255；分批每 16 槽让出一次执行片。任务初始化读取一次，运行期间不反复扫描完整列表。
- 每 500 毫秒读取 HP/MAXHP、MP/MAXMP、门派资源和当前出战珍兽数据；每秒发布一次有界快照。禁止用未确认单位的原生浮点比例代替人物 HP/MAXHP。
- 普通输出在现有敌对 NPC、场景、距离和双 ID 核对后执行，再检查游戏 IsEnable、CanDoAction 与冷却。资源和姿态等条件由客户端动作可用性参与判断；并没有独立复刻每个门派全部消耗公式。
- 自身恢复优先于珍兽喂养和输出。自身治疗选中经核对的本角色客户端 / 服务器 ID，避免把治疗发向怪物。健康状态检查也接入原棋局等待和移动回调。
- 共生、血祭类技能可分别绑定人物生命、气量阈值，并要求珍兽生命高于设定值。普通珍兽战斗手动技能再次验证当前怪物身份；珍兽 GUID、槽、名称、动作 ID 和出战状态变化即停止。攻击类珍兽技能至少间隔 3 秒。
- 同一时刻只允许一个维护动作等待反馈。恢复必须看到对应生命 / 气量增加；自身增益和珍兽攻击用冷却变化确认已提交，不能据此声称效果命中。8 秒未确认则停止、不重复提交。口粮缺失也通过没有恢复反馈停止，不循环调用喂养。
- 死亡、无有效生命上限、低血量且没有可用恢复、珍兽死亡或快乐度不足都会停止。恢复后的短间隔也持续检查生命。

游戏 Lua 使用该任务自己的持久子环境；读取和维护动作不逐项跨进程 IPC。快照通过版本 2 控制通道回传，限制 64 KiB；Worker 输出接收限制 256 KiB。只读检查结束不发送停止移动，其他任务结束仍保留原清理动作。新旧引擎协议不同，已经加载旧引擎的游戏需要退出后重新启动；本轮没有替用户关闭游戏。

## 明确待验收 / 待适配

这是宿主代码和离线验证完成，不等于所有门派技能、所有珍兽技能已实机通过。普通动作的可用状态依赖当前目标和游戏状态；不可用不能直接标成未学会或被动。自动、被动技能不保证能手动施放。已知地点选择、阵法、引导及特殊技能会明确阻止；未知特殊技能仍需要按实际客户端逐项适配。

本批没有实现队友治疗、自动复活、自动出战 / 收回、自动驯养、口粮购买、药品自动购买或完整门派技能效果 / Buff 解释器；也未接入新的副本主流程。现有棋局与通用副本战斗共用这批维护能力。珍兽列表及 API 参数依据本机接口注册和原说明静态核对，真实 GUID、血量、手动 / 自动技能分类、施放目标及效果必须在线对照。

Lua 5.4 仍有 16 MiB 堆、指令和执行片限额，复用原有停止与进程退出清理。原生游戏函数不能硬抢占，游戏自己的 Lua 堆也不包含在该 16 MiB 中。本轮未做长期多开性能测试，不能据离线结果承诺所有游戏负载均无卡顿。

## 验证与构建

CMake 新增 TLBBBattleFixture，使用本机官方 LuaPlus.dll，在本程序自己的进程里执行真实 Lua 5.0 片段，与 Lua 5.4 维护代码联动；不加载原脚本 DLL，不绑定真实 Game.exe。验证项目包含恢复优先级、反馈超时、冷却不能冒充回血、身份替换、技能变化、施放前可用性、动作异常后不重发及读数边界。核心测试额外覆盖维护参数和跨角色复制，UI 测试覆盖读数显示、技能加入配置、角色隔离及运行中禁用读取。

开发构建：

```powershell
Set-Location E:\game\tlbb\jb
. .\tools\env.ps1
cmake --build .tools\build\client --parallel 3
ctest --test-dir .tools\build\client --output-on-failure
& 'C:\Users\liqia\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -B tools\verify-development.py
```

自行生成安装器：

```powershell
Set-Location E:\game\tlbb\jb
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\build-installer.ps1
```

输出应为 dist/packages/TLBBClient-0.13.0-Setup.exe。该命令会构建、验证、收集完整程序与 Lua，再制作安装器；默认没有 ZIP。本轮没有执行该命令。开发版可执行文件位于 .tools/build/client/TLBB.exe，需要 tools/env.ps1 的 Qt 环境；它不是已制作好的独立安装目录。

最终验证：5 个 CTest 目标全部通过，43 组核心检查、130 项游戏 Lua 片段、42 项战斗维护 SDK 检查、25 项原生界面检查通过；原棋局 605 条指令及原包装文件哈希复核通过。证据见 artifacts/battle-maintenance-0.13.0/verification.json。实机与长期多开未测，本轮未生成安装器、ZIP 或完整发布目录。
