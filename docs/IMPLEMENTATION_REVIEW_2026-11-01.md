## 已确认缺陷与实施缺口

### R01 / P1：合法副本结果被本角色击杀数拦截

证据：`src/worker.cpp:369–374` 在读取/认可 task_result 前，要求非棋局战斗 `kills >= combat_kill_goal`；`src/session_panel.cpp:97` 默认目标为 1。

影响：峨嵋只治疗、队友完成击杀、当天上限/已完成而直接返回，均可能有合法副本回执却没有本角色击杀。燕子坞本轮夹具实际有两条 Completed 且 casts=0：今日次数已满（used=2，无入场）和队友完成/只治疗（used=1，已离场）。现有 `tests/yanzi_tests.hpp` 验证 VM 和回执，未经过 Worker 的这层检查。

修复：有专属完成契约的任务按契约校验有效终态；纯击杀任务才按击杀目标判定。对 already_done/limit_reached、只治疗及队员增加 Worker→事件→FlowRunner 全链路回归。

### R02 / P1：部分战斗任务以少量击杀充当完成验证

证据：`src/worker.cpp:374` 发出 completed 时把 `legacyCombat || verified(receipt)` 作为 verified。128 个通用原任务没有声明专属 validation_contract；通用宿主仅对特定三神幻境入口补回执，其余正常返回只记录脚本结束。

影响：无契约战斗任务只要达到默认击杀目标（1）并返回，就能被标为已验证，未必有该副本的终场/交付/离场证据。相反，原战斗框架如没有更新统一击杀计数，也可能实际执行后被拒绝。不能将两种计数语义混用。

修复：分别声明纯战斗目标、完整任务、副本完成条件。未知完成状态保留为未核验；不以 combat 布尔值直接设置 verified。

### R03 / P1：原规则需要的运行接口仍不完整

证据：`scripts/legacy/modules/original_generic_host.lua:95–98` 中 EnumMemberInfo、CallFun、R_M、GetOpenLootID 等仍是 missing()；部分分支检测到已出战珍兽直接报“场景珍兽对象 ID 读取尚未接入”（127 行）。

本轮生产入口启动诊断复现：挑战缥缈峰、王陵及满队琅嬛福地/困难版因 EnumMemberInfo 停止；三神幻境的场内诊断到 Player:GetBuff 缺口（该诊断显式跳过拾取以暴露后续问题，不能据此认为拾取已完成）。夹具未提供的 snippet 26 等错误仅属于夹具覆盖不足，不算真实游戏故障。

`resident.lua:119–126` 的原接口枚举仍拒绝玩家、珍兽和包裹；`resident.lua:82` 将未提供的 title 置空。实际 typed 快照和新包裹接口已在独立流程使用，却未统一映射到原框架。少室山的心魔头顶标记、首领当前目标和分类陷阱不在当前通用 Object 字段中。

修复：优先把现有真实队伍/Buff/包裹能力按原接口契约适配，补当前目标/头顶标记等缺失字段。读取失败、真实空集合、没有该属性必须区分，不能固定空标题/空列表使必要机制静默失效。师门仍需各任务类型的必要数据与结果契约，不能仅凭源码编译成功认定可用。

### R04 / P1：人工暂停/停止未统一停止持续攻击

证据：`src/resident_bridge.cpp` 的 Manager::finish 和 Pause 都调用 stop_motion；该操作只调用当前坐标移动函数，不选择自身或执行攻击停止。Lua 自身的 `dungeon_api.stopAttack` 才有选择自身并核对目标的步骤。强制 Stop 会销毁 VM，不会继续执行脚本尾部清理。

影响：暂停、解绑、异常或控制器断开后，没有代码保证已经启动的普攻/攻击追击停止；珍兽已有攻击也没有统一处置。此项为代码缺失，实际游戏持续动作尚未在线复现。

修复：原生控制层提供有身份核对的统一停攻/停走；角色纯读取任务不改变目标。按配置处理宠物，停止后不自动恢复出战。覆盖 Pause/Stop/End/超时/控制器退出等路径。

### R05 / P1：离线通过未阻止关键接口缺失

证据：`tests/resident_tests.hpp:101–108` 等启动诊断把 state/error 写入 JSON，并未断言指定必要流程成功或无 missing API；112 个原源码切换主要测试能构建脚本。独立副本测试也未覆盖 Worker 终态处理，遗漏 R01。

修复：诊断保留，用于探索；另为每个宣布可测试的任务建立明确前提下的关键步骤及终态断言。发布检查分别记录“可构建、接口齐全、离线流程通过、用户实测”，缺必要接口不能通过该任务的就绪检查。

### R06 / P2：原源码热更新索引不刷新

证据：`include/original_library.hpp:22–28` 按 base 路径静态缓存源码 index；相同目录再次启动任务不会重读。35 行每次校验源码哈希。Worker 重载只提示原规则下次任务生效，没有清除此缓存。

影响：修改原源码及对应 index 后，同一 Worker 仍可能拿旧哈希拒绝新源码；只改 Lua 更会直接校验失败。当前不能保证外置原源码“改完下一次任务即可生效”。

修复：按索引修订/哈希或明确重载失效缓存；将源码与索引作为一致快照验证。运行中保持当前规则，下次任务原子切换新快照。

### R07 / P2：跨城传送缺实际资料

证据：`scripts/navigation/catalog.json` 仅列苏州、洛阳；城市 NPC 名称/坐标/选项为空且 enabled=false、verified=false，没有大理→苏州→太湖的已核对线路。

影响：执行器有规划逻辑，实际仍依赖游戏自动寻路及对应确认窗口；不能保证从任意主城直达副本入口。

修复：填实际城市边、NPC、菜单和到达场景，覆盖跨场景确认框，并按每条已核验线路测试。没有资料的路线明确说明依赖游戏寻路。

### R08 / P2：配置可读性仍有大面积欠账

当前目录有 340 个设置 label 含 bjk/xzk 等原控件键；部分编号选择没有对应选项语义。很多开关即使能传进脚本，用户也难以正确配置。

修复：按任务所读配置整理，确认默认值/单位/索引与范围；确定枚举改下拉，复杂文本给语法和示例，未知项不作为已落实功能展示。

### R09 / P3：运行资源携带可精简的旧数据

当前资源内容约 12.56 MiB（13,172,412 字节），rcc 13,305,415 字节。原源码 5,033,191 字节；原库 4,567,064 字节，其中旧 rules-*.bin 与 custom-sources.bin 合计 4,156,343 字节。当前 originalSourceChunk/originalRuleClosure 和打包源码验证读取源码与索引，运行路径未发现读取这些旧二进制分片。

修复：先核对剩余工具/兼容读取，再从运行资源中排除旧分片，分析证据保留在工程中。现有库索引仍用于映射，不可一起删除。此项是体积优化，不代表已经发现泄漏；本轮无长期多开/游戏内存性能测量。
