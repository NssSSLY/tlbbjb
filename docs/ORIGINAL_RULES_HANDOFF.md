# 0.12.0 原副本规则接入

日期：2026-10-25。用户要求优先采用目标程序的原 Lua 规则，并明确要求本轮不生成安装包、压缩包，只修改、验证项目并说明手动构建方法。

## 当前制作方式

本轮首次直接接入原【副本】刷棋.lua 的控制流程，入口为 scripts/legacy/original/qiju.lua。原文件以标准 Lua 5.4 字节码嵌在用户提供的 dfz64.dll 中，并非明文 Lua。工具仅将 GBK 字符串转为 UTF-8；605 条指令、全部数值、闭包布局和分支保持原样。运行时由本程序的 Lua 5.4 VM 执行，未加载原程序的 DLL。

同时直接采用 13 个原公共函数：对象名称/类别/数值过滤、排序、表辅助函数和 Team.IsCountReady。源模块、原始哈希、转换后哈希与指令摘要保存在 qiju.provenance.json、artifacts/original-combat-0.12.0/filter-provenance.json。

scripts/legacy/modules/original_combat.lua 是本程序编写的宿主适配层：提供对象快照、战斗动作、带回调的移动、NPC 交互、配置读取和本轮完成回执。它没有另写棋局主循环。原指令保持不变不等于完整复制原系统行为；宿主接口、保护约束及未接功能仍有差异。

之前的 combat.lua 和 adapted/zhenlong.lua 属于本程序重建；现在参数页明确提供“原规则 / 兼容重建”选择，默认原规则。外部兼容引擎只支持兼容重建，原规则需要游戏内 Lua。

## 已修正的场景号

原脚本的 m_teamCount 捕获父寄存器 1，初值 3；m_fubenSceneID 捕获寄存器 3，初值 61。之前重建版把 3 误当作棋局场景号。本轮将默认值、重建兼容层及 Worker 离场判定改为 61；读取旧棋局配置时将旧错误值 3 归一化为 61，普通“副本内战斗”的用户场景号不受影响。

静态解析器也修复了 Lua 5.4 数值标签：3 是整数、19 是浮点。旧静态列表里的某些整数被错误显示为极小浮点数。新的 32 份副本列表放在 artifacts/original-combat-0.12.0/listings/；旧还原任务还需要分批依据新列表复核，不能把旧列表的数值展示当作正确依据。

## 界面与配置

- 规则来源：原规则、兼容重建。
- 入场方式：自动入场、已在副本。原自动入场限苏州或苏州休息室；其他城市的传送仍待适配。
- 原规则·快速入场：绑定原 ReadConfigBool("ZH","xzk190")。
- 原规则·入场人数：默认 3，范围 3–6，属于对原局部人数参数的宿主补充覆盖，不是冒充原读取键。
- 输出技能、范围、最低血量、技能间隔、停滞与总超时沿用本角色战斗配置。

快速入场和人数仅在“原规则 + 自动入场”时启用。参数声明来自任务目录 settings，bool/number/text/choice 都由通用编辑器生成；来源分组与键放在提示中。新配置是每个角色独立保存的任务参数，不改账号或身份数据。缺少映射的原配置读取会明确报错。

直接配置读取清单见 docs/DUNGEON_RULE_CONFIGS.md；共核对 32 个副本，动态键及公共模块的间接配置尚未全部展开。尚未接入的副本不会因列出配置就变成可执行任务。

## 本批边界

原棋局支持已有队伍的入场、选怪、基础攻击/已学技能、原巡查流程及齐圣离场。远古棋魂必须在本轮被观察为活体，且同一客户端/服务器 ID 连续两次死亡读数确认后，才记录 Boss 完成；退出场景 61 后再报告成功。消失、ID 复用、未确认入场、未确认通关都不能算成功。入场选项不重复提交。

原脚本首次刷怪前会一直等待；25 秒巡查/90 秒离场的逻辑在见怪后才成立。保留该流程，首次空场等待由外层任务总超时兜底，不能把等待状态报告成通关。

未接入：拾取、自动换线、自动复活、当日次数读取、自动组队与跨城传送。拾取和换线明确跳过并记日志；低血量/死亡停止等待人工。本批 IsHuodongComplete 只提供单轮 Boss+离场回执，不冒充真实当日次数查询。IsMount 使用已适配的下坐骑请求处理，未复制原程序的原生 Buff 查询。提示历史仅覆盖当前可读提示，不复制原程序的一小时历史记录。

原任务字节码没有恢复为可编辑的完整明文源码。适配层与参数可以直接修改 Lua；需要修改原任务内部流程时，应取得明文源码或继续单独还原，不能手改嵌入字节串。

## 验证与重现

在自建窗口、伪角色/怪物状态和官方 LuaPlus SDK 中验证，不操作真实角色。检查包括手动/自动入场、原配置分支、对象筛选位置参数、技能与死亡确认、低血量、ID 复用、不确定请求、入场不重发、初刷等待与战后空场。真实伤害、冷却、停止持续攻击、完整副本和长期多开仍待实机验收。

源码与生成规则的备份在 artifacts/pre-original-rules-0.12.0/。生成规则（只生成 Lua 与取证文件，不制作安装包）：

```powershell
. .\tools\env.ps1
& 'C:\Users\liqia\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -B tools\original-lua-rules.py --generate
```

手动生成安装器：

```powershell
Set-Location E:\game\tlbb\jb
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\build-installer.ps1
```

脚本会编译、执行验证、收集全部内置 Lua，再制作 dist/packages/TLBBClient-0.12.0-Setup.exe。默认不生成 ZIP；只有显式追加 -IncludeZip 才生成完整解压包。本轮没有执行该安装器构建命令，也没有执行安装。
