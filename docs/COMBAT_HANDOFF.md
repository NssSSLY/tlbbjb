## 底层证据与接口

只适配 include/live_layout.hpp 中的 Game.exe 哈希，仍核对 CEGUIBase.dll 与 LuaPlus.dll。静态证据保存在 artifacts/combat-research/。没有更改游戏文件。

1. CObjectManager 的虚表 RVA 0xc2fb18。+0xe0/+0xe8 是客户端 ID 红黑树及节点数；+0xf0 是服务器 ID 树。节点的 +0x20 为 ID、+0x28 为对象，左右子树 +0/+0x10。依据：0x5d60d0、0x5d6130。
2. CObject_PlayerNPC 的虚表 RVA 0xc39b48；玩家、珍兽、召唤物、包裹和场景物件虚表不匹配即排除。对象 +0x28 为客户端 ID（虚函数 +0x78），+0x2c 为服务器 ID（+0x80）。+0x48 为已移除状态，位置沿用已实测的 +0x4c/+0x54。
3. 目标生命沿用 Target:GetHPPercent 的静态实现：对象 +0x228 → +8 → float +8，只接受 0–100 内有限值，目标死亡只判断零值。角色低血量保护使用已接入的 Player:GetData("HP") / Player:GetData("MAXHP") 比例，不依赖该原生浮点数的百分比单位。敌对性沿用 SetMainTargetFromList 的判定：全局 +0x1054eb8，虚函数 +0x2c0(player,npc,0)，非零为敌对。实际怪物与人物血量读数仍需实机对照。
4. DataPool:SelectAsTargetByObjID 参数实际为**服务器 ID**（查询管理器 +0x90）。Target:GetData("NPCID") 实际返回**客户端 ID**（虚函数 +0x78）。Target:GetServerId2ClientId 的反汇编证明该映射。施放前重新核对 ID、类型、敌对、生命、范围、场景；选中后再次核对 NPCID。
5. 技能通过 EnumAction(i,"skill") 0–255 按 GetName 精确匹配；Lua_CheckActionItemCoolDown(GetID()) 非零则跳过。具名技能借用现有 ActionButton 的 SetActionItem/DoAction，并恢复其原值；DoAction 抛错也先恢复。基础攻击调用 Player:UseSkill()（反汇编为无额外参数的默认攻击）。动作回执只代表调用已提交，后续靠目标生命变化判断进展。

游戏片段增加 30 CombatScan / 31 CombatCast / 32 CombatSkill / 33 CombatName。片段参数类型和范围固定，不接受任意游戏代码。CombatScan 在游戏窗口线程内只读；不对真实游戏做远程线程调用。

## Lua 与棋局流程

scripts/legacy/combat.lua 是本程序重建的战斗层。adapted/zhenlong.lua 与 adapted/dungeon_combat.lua 是新入口，不是原文件逐字节复制。manifest 的 adapted=true / rules_modified=true / live_verified=false 明确记录这一点。

棋局依据原副本/【副本】刷棋.lua，反汇编 002b8890.listing.txt：场景 3；苏州张弈国 (267,242)，入场选项“珍珑棋局”及 #{QJYH_150315_02}；六个巡查点 (45,45)、(82,45)、(82,82)、(45,82)、(45,64)、(64,64)；25 秒无怪开始巡查；90 秒无怪超时；远古棋魂死亡后找齐圣 (40,40) 选“确定”离场。

本程序增加的完成约束：同一客户端+服务器 ID 连续两次死亡读数才能计入击杀；消失、离开范围、ID 复用均不计击杀。棋局必须看见名为“远古棋魂”的目标并确认死亡，且最终读到场景已离开 3，才报告完成。空场不能算通关。

原程序的刷棋拾取、换线、队伍跟随、死亡自动复活、活动完成提示检测没有迁移；原低/高等级分支只接入普通入场选项。原 Lua 中复杂的 FubenAttack/技能控制函数尚未整体兼容，不能据此宣称其他副本 Lua 可直接运行。燕子坞、四绝庄、少室山、兵圣等仍需各自入场、首领机制、任务状态与离场适配。

## 性能与故障边界

- 每个角色仍只有一个 Worker 和一个执行器，沿用 Worker 内存/CPU Job 配额、Lua 16 MiB 限额及单次恢复指令/时间预算。
- 战斗循环 Sleep 500 ms；最小施放间隔 750 ms，默认 1000 ms。基础攻击补发最短 1500 ms。具名技能仍检查游戏冷却。
- 新目标搜索最多遍历 512 个场景对象、64 个栈项，游戏线程单次扫描读预算 12 ms。已有目标只做深度 ≤32 的树查找。超限、坏指针、NaN、坏树或身份变化均停止，不当作空场。
- 每任务最多 6000 次有效动作、12000 次战斗请求；非战斗原任务仍保持 600 次。默认生命无下降 60 秒即停，可配 10–300 秒；总超时仍有限。
- 任何动作回执不确定都结束该次任务，不重发该动作。停止本身不确定时提示人工接管。
- 以上是资源限制和离线证据；没有真实多开长时间性能验收，不能保证所有游戏场景绝不卡顿。
