此前真实尝试停在密码提交前，最新子状态修正尚未完成真实游戏登录验收。用户确认游戏及旧启动器由其手动关闭；没有发出关闭游戏命令。0.4.3 本轮只分析第三方资料并加入参考路线配置，没有继续认证。以下原始记录保留作设计依据。

本次在 C++ 启动链中接入真实游戏登录适配器，未修改游戏文件。核心文件为 include/login_protocol.hpp、src/login_bridge.cpp、src/login_client.cpp；启动器接线在 src/launcher_window.cpp。该适配器需要在登录界面完成真实账号验收，当前在线角色只做只读探测。

## 执行路径

1. 开始游戏前检查所选账号的登录名、本机 DPAPI 凭据、大区、服务器和角色槽位，冻结本次配置。
2. 启动官方 Launch.exe。若存在可识别的标准“开始游戏”按钮，发送一次按钮消息；自绘按钮或更新界面需要人工点击官方启动器。跟踪本次启动的唯一新 Game.exe，保留进程创建时间，已有在线角色不作为自动登录目标。
3. 自动绑定后启动独立 --login-worker，命令行只传进程身份、配置目录和账号 UUID/区服/槽位，不传密码。
4. 对 Game.exe、CEGUIBase.dll 校验 SHA256。原生桥接在游戏窗口线程执行白名单命令，不使用系统鼠标或键盘。
5. 按官方区服目录精确匹配大区和服务器，调用游戏已有 GameProduceLogin:SelectLoginServer。账号界面再次读取游戏实际选中区服，匹配后才允许填充账号密码。
6. 按需要切换普通账号或邮箱账号输入方式，通过 CEGUI 原生控件填入账号、密码，触发一次登录。密码不拼接进 Lua 源码；临时明文和映射在使用后清零。
7. 角色界面读取 1/2/3 槽位昵称，拒绝空槽和创建角色入口；先选角色，核对对应高亮后点击进入游戏。
8. 连续两次确认真实地图/角色状态后，保存当前账号和区服下的角色名称。未经确认不把 PID 或窗口标题当成昵称。

## 控制与资源

- 单次账号提交，不自动重试密码；普通阶段 45 秒无变化停止，总时限 5 分钟。
- 已识别的密保/验证/提示窗口转为等待人工处理。人工处理后继续轮询；未知界面保持等待并按时限停止，不乱点确认。
- 点击“取消登录”、End 解绑目标游戏、停止全部任务、游戏退出和软件退出都会结束对应登录子进程；不结束游戏进程。
- 登录进程沿用 Worker Job 的 192 MiB 单进程、512 MiB 合计和 CPU 10% 上限。登录轮询每秒一次，映射载荷小于 4 KiB，宿主输出缓冲上限 64 KiB。短测通过不代表已经完成长期多开性能验收。
- 密码必须在账号编辑中选择“保存密码以自动登录（本机加密）”。旧版本未保存的密码无法恢复，需要重新输入一次。凭据绑定 Windows 用户，不随安装包分发。
