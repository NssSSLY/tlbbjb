# 副本扫荡校验与完整副本后续工作

## 本次可供游戏内测试的项目

面板上的“扫荡燕子”和“扫荡四绝”继续调用已有的原 Lua 文件，新增宿主负责运行前和运行后的状态核验。原 Lua 文件没有更改。两项使用游戏内 Lua 引擎，具体实现见 `scripts/legacy/modules/original_sweep_host.lua` 和共享的 `scripts/legacy/compat.lua`。

运行前确认目标副本、剩余次数、点数和没有其他扫荡在进行；每轮确认剩余次数减少且进行状态结束，才继续下一轮。页面、首领或计数状态不明时停止，避免重复提交。无资格或点数不足与完成分别报告。扫荡前后的清包、出售和存仓没有接入。

游戏 SDK 的固定片段最多容纳现有的 7 个数值和副本名称，总次数使用独立的只读游戏 Lua 查询，并与剩余次数核对。两个入口分别验证了 14 种模拟状态，包括成功两轮、已无次数、无资格、点数不足、找不到目标、页面不出现、首领状态不推进、次数不变、身份变化、已有扫荡、部分完成后点数耗尽、总次数无效、页面持续加载及扫荡迟迟不结束。验证使用模拟接口和 SDK 测试夹具，没有实际进入游戏。

## 构建

开发输出为 `.tools/build/client-0.15.0/`。需要安装包时，在 PowerShell 中手动运行：

```powershell
Set-Location E:\game\tlbb\jb
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\build-installer.ps1
```

本次未运行安装包或 ZIP 构建脚本。使用更新后的游戏桥接 DLL 测试时应重新启动脚本客户端并重新绑定；若游戏进程仍持有旧 DLL，还需重启对应游戏进程后加载新版本。
