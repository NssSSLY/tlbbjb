# 0.11.0 游戏内 Lua 执行改造

2026-10-25，工作目录 E:\game\tlbb\jb。改造前快照及文件哈希在 artifacts/pre-resident-0.11.0/，没有覆盖旧的 0.10.0 发布包。

## 目的与运行方式

此前是外部 Worker 中的 Lua 5.4 协程每提出一个游戏操作，就通过映射文件、WH_GETMESSAGE 和游戏桥接往返一次。现在常规 legacy 任务默认选择“游戏内 Lua”：一次传入 Lua、模块和参数快照，在各自 Game.exe 中由 TLBBEngine.dll 持有 Lua 5.4 VM；每 20 ms 在游戏窗口线程中恢复一次。Sleep 让出执行权，后台 Worker 每 500 ms 查询状态，负责控制和进程生命周期，不再逐个转发游戏操作。Qt 只在外部客户端中运行。

GetLuaValue(source, format, count) 同步调用官方 LuaPlus.dll 的游戏 Lua 5.0 状态。没有旧的字符串白名单匹配，也没有旧的 512 字节结果上限。每条代码最多 128 KiB、最多 32 个标量返回，游戏编码下累计字符串最多 64 KiB；支持 n/s/b 格式或空格式自动返回数字、字符串、布尔与 nil。使用一个任务独有的 SDK 子状态和私有全局表，回退读取游戏全局；连续调用保留任务自己的变量，不改父状态的栈。该环境用于减少命名污染，不能作为隔离任意可信代码的安全边界。

compat.lua 中原有同名接口继续使用已经适配的原生调用，但在游戏进程内直接调用，不走外部 IPC。resident.lua 扩展 GetLuaValue、Player:GetData、模块加载和对象查询。仍有“外部兼容”选项供对照。独立的每日签到任务继续保留旧的月度状态两次确认流程；登录也保留已接入的专用流程，不在这批中重写。

## 迁移范围

既有脚本来源混合：明文原 Lua 逐字节保留；部分任务按静态字节码还原；compat.lua 和 combat.lua 由本程序实现，棋局是依据原规则重建。manifest.json 分别记录 original_sha256、reconstructed、adapted、rules_modified 和 live_verified。本轮改变执行位置，没有把 318 个静态解析模块全部变成可运行脚本，也没有加载或分发第三方 dfz64.dll。

EnumObjects()/Game.Objects() 返回当前 NPC 类型对象的 id、server_id、name、x、y、hp、hostile、dst。遍历上限 512 个、栈上限 64，核对对象类型、客户端/服务器 ID、生命、移除标记及管理器身份；排除玩家、珍兽、包裹等其他类型。Enum2XByName(name) 和 Enum2XByClass("怪物"/"NPC") 只接入单参数子集；原程序的额外筛选参数明确报未适配，不能当作全 ABI 兼容。标题、玩家、掉落等枚举仍需独立适配。

## 如何增加 Lua

1. 公共模块放在 scripts/builtin/legacy/modules/*.lua，文件名作为 LoadScript 的名称；单个最多 256 KiB、最多 64 个、与任务及兼容层合计小于 512 KiB。内置 character_status.lua 是仅查询生命的示例。
2. 新任务入口放在 legacy 下，在 legacy/manifest.json 中增加唯一 id、entry、name、adapter=tlzz_compat_v1；同时在 tasks/catalog.json 增加 family=legacy 的同 id 入口及参数。任务 id 使用小写字母、数字、下划线，超时 10–7200 秒。
3. 现有任务和模块修改后，下次启动任务自动加载新快照；运行中不会替换、重启或重放任务。目录入口增加后重开面板/启动器以读取新目录。直接调用游戏已注册 Lua API 不必重新编译；新增 C++ 原生 ABI 或界面控件仍需重编译。源码发布时维护 scripts/ 和 design/task-catalog.json，再生成完整软件包。

## 限制与故障处理

- 每个游戏一个任务 VM。Lua 5.4 分配器限制 16 MiB；单片段约 2 ms/25,000 指令，每次恢复最多 8 个宿主调用；连续无 Sleep 超过一千万指令失败。暂停不推进任务的 Sleep 时钟，任务超时仍按墙钟计时。
- Lua 5.4 的任务禁止注册 __gc 回收回调。异常清理测试曾触发 30 秒超时；查看本地 Lua 源码 lgc.c 确认回收回调会关闭指令钩子，单纯给 lua_close 安装钩子无效。现由受控 setmetatable 在注册时拒绝 __gc，回归要求明确失败并释放 VM。游戏 Lua 内部的原生回收仍由游戏维护。
- 游戏 Lua 5.0 片段带约 2 ms/50,000 指令检查。它使用游戏自己的内存分配器，**不在 Lua 5.4 的 16 MiB 上限内**。原生 C 函数、长字符串库操作和游戏内部调用不能被这些指令钩子硬抢占。不能据此保证任意脚本不会拖慢或崩溃游戏。
- Worker 仍受外部 Job 的内存/CPU 配额约束，游戏进程不加入这个 Job。任务结束、失败、停止时销毁 Lua 5.4 VM 与游戏 SDK 子状态、取消任务定时器、关闭监控句柄。合并 DLL 被固定在游戏中直到游戏退出，避免回调仍在执行时卸载代码；这是常驻代码，不是常驻任务。
- Worker 消失或超过 5 秒不再查询时，游戏定时器停止任务。这需要游戏窗口线程仍能运行；阻塞在原生函数中时无法承诺立即响应。处理重入时先延后暂停/停止，不能在 Lua 回调内销毁当前 VM。
- 控制请求结果不确定时不重复启动或重发动作，也不覆盖正在执行的映射包。原脚本自身的循环和重试由脚本决定；本程序无法替任意代码保证“恰好一次”。停止通过已适配移动调用请求停在当前位置，不能撤销已提交的支付、物品操作或游戏动作。
- 允许支付/交易/下线开关只约束兼容接口。**GetLuaValue 直调可自行调用这些操作，也可能删除物品或下线**；不能再称这些开关全面约束任意 Lua。只运行自己审查并信任的脚本。程序没有新增销毁按钮或销毁任务。

## 打包与验收

三个桥接 DLL 合并为一个 TLBBEngine.dll，保留四种 Hook 入口。移除当前 Widgets 客户端未用的 QtNetwork、触摸、图像格式、网络信息和 TLS 插件。Qt Core/Gui/Widgets、Windows 平台插件和编译运行库仍需要随包部署，不能只分发一个 EXE。

离线验证覆盖：10,000 次同步返回及分片续执行不重放；暂停/Sleep；200 次启动停止后释放 Lua；死循环和内存上限；清单内所有兼容入口编译；模块和新增 API；棋局生命周期、低血量、未知结果；官方游戏 SDK 的中文、nil 位置、长返回、私有环境、错误预算及父栈保留；合并 DLL 的四个导出及自建窗口 Hook。测试使用本程序自建窗口与伪游戏状态，没有执行用户游戏动作。

当前不能宣称本轮已通过真实副本或多开长时间性能验收。控制器/VM 的离线行为与真实伤害、冷却、停止持续攻击、完整通关分别记录。发布验证、资源采样、基准和软件包清单放在 artifacts/ 的 0.11.0 文件中。
