# 启动器与单游戏任务面板交互规格

2026-10-25 更新：用户提供六张功能页面后，0.5.0 单游戏面板已按 UI_REFERENCE_R3.md 调整为九页、功能目录、顺序/定时双列表。小启动器、每游戏独立面板、Home/End 和配置隔离保留。本文以下十 Tab 内容作为历史设计，当前入口和能力以 UI_REFERENCE_R3.md / PROGRESS.md 为准。

版本：设计修订 0.3-r2；日期：2026-10-24。取代前版“角色侧栏＋集中工作台”。当前发布 EXE 仍为 0.2，本文件不代表新界面或登录能力已经实现。

实现更新：当前发布已为 0.3.0，小启动器、十 Tab 独立面板、两路径绑定、上部提示和完整安装器已实现。最新用户修订要求唯一“开始游戏”按钮＋允许多开、未有缓存时可选角色 1/2/3 槽位；真实昵称/认证/选角未适配。下面原设计中的自动登录属于后续目标，实际边界以 PROGRESS.md / 根 README 为准。

## 1. 产品结构

一个软件包、一个后台宿主；启动显示小型启动器，用于安装路径、账号、区服和角色登录；每个游戏各自呼出自己的任务面板。没有集中展示所有角色任务的主界面，没有角色常驻侧栏。

```text
TLBB.exe（单实例宿主 / 托盘）
  ├─ LauncherWindow：游戏目录、已保存账号、区服、角色、启动登录
  └─ SessionRegistry（后台，不作为集中任务窗口）
       ├─ 游戏进程 A ─ SessionPanel A ─ 独立配置 / 队列 / Worker
       ├─ 游戏进程 B ─ SessionPanel B ─ 独立配置 / 队列 / Worker
       └─ 游戏进程 C ─ SessionPanel C ─ 独立配置 / 队列 / Worker
```

三个进程是架构示例，不代表已解除游戏双开限制。游戏可启动数量与任务面板结构分开验收。

任务面板为独立 Qt 顶层工具窗口，固定归属目标游戏 HWND；不要求将绘制层注入游戏或修改渲染。原生窗口标题栏保留系统移动/关闭能力；客户区第一行就是 Tab。无自绘大标题、简介、横幅和账号总览。角色、区服和状态只在底部单行显示，完整身份在“设置”查看。

## 2. 快捷键与窗口生命周期

| 操作 | 结果 |
|---|---|
| 游戏 A 前台按 Home | 校验 A 的 PID、创建时间、HWND、版本；首次绑定并创建 A 的面板，已有则呼出 A；不自动开始任务 |
| 游戏 B 前台按 Home | 创建或呼出 B 的面板，不把 A 的面板切换成 B |
| 当前游戏或其面板按 End | 停止并解绑该会话，关闭该面板、退出其 Worker；不退出游戏、不删除配置 |
| Insert | 显示/隐藏当前游戏对应面板；没有目标上下文时不误操作其他面板 |
| 面板右上角关闭 | 隐藏该面板；显式“解绑”才解除绑定 |
| 游戏最小化 | 隐藏其面板、记录可见状态；已启动任务按配置后台运行 |
| 游戏退出 / 身份 token 失效 | 结束对应 Worker、关闭面板、保存配置；其他游戏继续 |
| 托盘“退出软件” | 有序停止全部 Worker，清理面板和句柄，退出宿主；不强杀游戏 |

快捷键必须使用事件所属游戏或面板固定 session_id 路由，不能复用全局 selected_ 作为动作目标。Home/End 不在浏览器等非游戏上下文抢占；面板文本输入时保留编辑键语义；重复 Home 不重复创建面板或 Worker。

每个面板独立保存位置、尺寸、当前 Tab 和任务草稿。后台会话表是实现细节，不恢复为集中任务管理页。

## 3. 小型启动器

建议约 680×430，可调整尺寸。首次未配置目录显示目录输入、浏览/检测、保存；配置后主体为已保存账号列表和当前账号登录选项。

字段：游戏目录、账号别名/账号标识、凭据保存选项、大区、服务器、该服务器角色、启动并登录、仅启动游戏。账号列表可以展示多个已保存账号，不包含角色任务配置。

目录检测至少核对启动器、目标产品与可执行文件存在；保存路径不代表版本适配通过。启动走官方启动器，跟踪本次启动链、目标进程创建时间与最终窗口；多候选不猜测绑定。

区服来自版本化目录，可刷新；本轮草图只有示例项，不声称目录完整。服务器使用稳定 ID，名称允许更新。账号可选择多个服务器，角色按账号＋产品＋区服分组。

凭据使用本机用户加密保护，保存为安装目录 data/ 下的加密文件，JSON 仅保存凭据引用。Lua、日志、复制方案和普通导出不含密码；换电脑需重新录入密码。原型不接收真实密码、不连接认证。目录不可写时要求选择可写位置，不静默转存 C 盘。

关闭启动器默认隐藏到托盘，已运行会话继续。

## 4. 首次登录与角色记录

```text
首次账号 / 区服：角色列表未知
  → 官方启动器 → 区服 → 认证（必要时人工）
  → 角色选择 / 游戏世界 → 身份核验
  → 保存实际读取的角色 → 下次选择该角色自动登录
```

未登录时不提前扫描不存在的角色列表。可先保存账号、区服及角色 1/2/3 槽位。主按钮始终为“开始游戏”；有可靠昵称后只替换槽位显示文字，保留槽位/角色 ID 对应关系。自动认证/选角尚未适配时在游戏内手动登录，Home 仍可绑定。

角色选择界面能读完整列表时才缓存列表；只在游戏世界读到当前角色，则只记录当前角色，roster_complete=false，不冒充获得账号下所有角色。读取失败保留旧缓存并标记待刷新，不用空列表覆盖已有记录。

优先按稳定角色 ID 匹配，并校验账号、区服和名称；槽位只作提示，不能因排序变化就登录另一角色。改名、删除、跨服或缓存过期需刷新；未找到目标停在选择界面，不自动选第一项。

登录步骤为待启动、启动器就绪、选服、认证、等待人工、角色选择、进世界、身份核验、完成/失败，各有超时、有限重试和原因。验证码或身份挑战交人工。登录成功不隐式开始脚本；进游戏按 Home 呼出面板，再由用户开始。

断线重登为单独开关，恢复先核对完成记录，不重复交付、消耗或销毁。共享启动器上的登录操作可串行协调，不阻塞已进入世界的其他游戏队列。

## 5. 单游戏面板布局

实际窗口约 1000×620，兼容 900×560、125%/150% DPI。顶部直接排列功能 Tab，下方完整显示对应参数。无介绍占位。Tab 较多时原生换行/滚动，关键动作固定底部。

| Tab | 内容 |
|---|---|
| 副本 | 副本列表、次数、难度、完整通关/扫荡、队伍和关卡策略 |
| 日常 | 师门、打宝图、漕运；轮次、分支、物资、预算 |
| 活动 | 活动项、时段/场次、错过窗口策略、有效期 |
| 生活 | 种植、钓鱼、采矿、采药局部切换；地图/地点、资源、次数、等待/换点 |
| 挂机 | 刷怪、挖图、马贼；范围、目标、时长、图种与分支 |
| 技能 | 本角色门派、优先级、恢复/增益/输出、目标、珍兽和形态条件 |
| 拾取背包 | 拾取、保留、出售、存仓、销毁；名单、保护、预览 |
| 补给恢复 | 药品、库存、修理预算、满包、卡路/死亡/掉线 |
| 任务流程 | 此游戏的顺序队列、启停/上下移、时段、失败策略 |
| 设置 | Lua 列表/版本/重载、快捷键、当前绑定身份、复制/导入导出、诊断 |

底部只有开始流程、暂停/恢复、停止、保存、复制配置，以及单行角色/区服/任务状态。任务页“运行本项”仅运行该任务，“加入任务流程”加入顺序队列，两者目标明确。日志按需展开；未适配仅在任务旁小标记，启动检查失败再显示具体原因。没有永久大面积说明区。

任务页“选择玩法＋参数”，加入流程时生成独立节点快照。单任务执行也复用同一执行器，不产生两套争抢角色的动作逻辑。官方收录与已经适配继续分开。

## 6. 参数与队列

保留 task-catalog.json 的稳定 ID、来源、版本和适配状态。当前仅位置读取及洛阳近距离移动已验证，其余可配置但不可假执行。

种植：洛阳 360/317、作物、早/晚产、轮数、等待空地、收获策略、超时。钓鱼：地点、工具、时长/数量。采矿/采药：资源、路线、技能、换点。师门/漕运分别配分支和预算；打图、挖图、马贼分别为节点。副本区分通关与扫荡，资格和次数从实际状态核对。

单游戏仅一个角色动作执行器，多个游戏互相独立。刷怪/采集必须有数量、时长或结束时刻。限时活动在安全点插入，不在播种提交、交付或首领战强制切走。作物成熟观察可释放动作锁，但不同时指挥角色。

启动前核对身份、绑定、版本、能力、地图、配额、队伍、物资与冲突。未适配节点默认阻止启动，用户可显式禁用；日周重置按本服规则，过期活动拒绝启动。

失败为停止队列、跳过、有限重试或人工，默认停止。草稿、保存版、运行快照分开，修改下一安全点生效；保存不启动。Lua 候选失败保留旧版，不半更新。

## 7. 复制与后勤

“复制配置”按需打开对话框，选目标和范围、预览差异、独立复制。目标列表只出现在复制对话框，不成为常驻侧栏；支持覆盖所选或只填空。

排除账号、区服/登录身份、凭据、PID/窗口/创建 token、运行状态、历史和配额；不同门派跳过技能，不同服务器重验任务。运行中目标只更新草稿。源修改不影响目标。

拾取与背包处理分开。销毁默认关闭，任务必需、锁定、已装备、保留和未知物品优先保护；实际按稳定物品 ID 和属性匹配，不按模糊名称删除。先预览再启用，修改或复制后重新预览；执行前再次核验物品。原型无真实物品动作。

## 8. 安装包与软件目录

完整离线安装包为主，另提供同内容完整 ZIP。目录同时包含 EXE、DLL、Qt 运行库/插件、全部内置 Lua、任务描述、默认配置和版本清单，不需要开发工具或联网补运行库。建议 E:\TLBBClient，可选择其他可写目录。

详见 INSTALLATION_AND_LOGIN.md。新增 Lua 及其描述每次发布递归收集，不能只复制 luoyang_plant.lua。改 Lua 可候选重载；改 C++ 界面/接口须重编；仅加兼容脚本不必重编 EXE，但要重做完整安装包/ZIP。

升级替换内置程序/脚本，保留 data/、用户脚本和配置，迁移前备份。安装/升级不自动启用任务，不重新打开销毁。

## 9. 实现与性能

从 MainWindow 拆为 LauncherWindow、SessionManager、SessionPanel、AccountStore、RoleCache、ScriptRegistry、PackageBuilder。动作目标不依赖正在编辑的 selected_；面板固定 session_id，指令带 PID/创建 token/序号；销毁面板解除订阅与句柄。

一个宿主管托盘和窗口。Worker 按已绑定/运行会话隔离，不为所有已存账号/角色常驻创建 Worker，不为各 Tab 起进程。隐藏面板停止布局刷新，事件驱动并限频；日志有界，轮询退避，进程退出用事件处理。

沿用当前保护：单 Worker 提交 192 MiB、Worker Job 合计 512 MiB、CPU 硬上限 10%、日志视图 1000 块，游戏不纳入 Job。性能验收覆盖多会话、反复 Home/End、隐藏、重载、退出和持续采样，不能仅凭设计保证永不卡顿。

## 10. 落地顺序与边界

1. 拆启动器/单游戏面板，完成快捷键归属、独立 Tab、配置保存，保留真实移动。
2. 接目录/脚本描述、流程、复制和预检，用真实移动做实机回归。
3. 接账号/区服缓存、登录协调、角色列表/身份读取，再开放记忆角色自动登录。
4. 分别适配种植、NPC、物品、战斗等，真实结果验收后开放。
5. 生成完整安装包/ZIP，在无开发环境 Windows 上验证安装、脚本齐全、升级保留和卸载。

上述为分阶段规格；0.3.0 已完成绑定与安装包阶段，认证、昵称和完整游戏任务仍按真实结果逐项实现。0.2 历史包保留。
