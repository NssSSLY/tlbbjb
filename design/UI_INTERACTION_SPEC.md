# TLBB 多角色任务客户端界面与交互设计

> 已被 2026-10-24 用户修订取代。当前规格见 [UI_SESSION_SPEC.md](UI_SESSION_SPEC.md)。本文件仅保留前版记录；不要实现其集中工作台、角色侧栏或大标题布局。

版本：设计草案 0.3；日期：2026-10-24。此文件是设计规格，不代表 EXE 已具备下列全部功能。当前业务版本仍为 0.2，只验证过位置读取和洛阳近距离移动。

用户已明确：每个角色独立配置，支持批量复制；不以全队统一控制为默认模式。官网调查依据见 research/OFFICIAL_FINDINGS.md；任务目录见 task-catalog.json。

## 1. 主窗口结构

推荐实际 Windows 窗口 1440×900，兼容 1280×800，125%/150% DPI；小窗口允许折叠角色栏和参数详情。不要把六十种玩法各做成一个主 Tab。

```text
应用栏：TLBB 任务引擎                 全部暂停 | 紧急停止 | 托盘
┌ 角色列表 ──────┬ 当前编辑：角色 A / 区服 / 门派 / 绑定状态 ─────────┐
│ 角色 A        │ 执行台 | 任务库 | 流程编排 | 战斗技能 | 拾取后勤 | 登录角色 │
│ 角色 B        ├────────────────────────────────────────────────┤
│ 角色 C        │ 当前页面主区                    │ 选中条目详情     │
│               │                                 │                │
│ 复制配置      │                                 │                │
├───────────────┴────────────────────────────────────────────────┤
│ 当前角色：状态 / 正在执行的步骤 / 等待原因 / 保存与生效状态 / 日志入口 │
└────────────────────────────────────────────────────────────────┘
```

左侧是持久角色配置，不是 PID 清单。PID、窗口、进程创建时间是运行时绑定属性；游戏重启不产生一套新配置。未能可靠读取角色身份时，只能人工确认绑定，不按相似名字猜测。列表区分未登录、未绑定、已就绪、执行中、等待中、人工接管、异常。

顶部始终显示“正在编辑哪个角色”，按钮明确标注“当前角色”或“全部”。切换角色仅切换编辑上下文，不启动、停止或接管其他角色。

## 2. 六个主页面

| 页面 | 主要内容 | 不应放入的内容 |
|---|---|---|
| 执行台 | 当前队列、当前步骤与阶段、真实状态、下一步、等待/失败原因、开始/暂停/停止、最近日志 | 全量参数表和所有玩法开关 |
| 任务库 | 副本、日常、限时、生活、野外、工具分类；名称/俗称搜索；收藏；条件/适配状态；配置后加入队列 | 一排会直接执行未知任务的快捷按钮 |
| 流程编排 | 顺序列表、拖动/上下移、启停节点、目标次数/时长、完成与失败策略、等待窗口、条件检查、完成后的动作 | 首版复杂节点画布和任意代码编辑 |
| 战斗技能 | 门派/技能方案、输出优先级、治疗/自保/增益/解控、目标条件、珍兽策略、形态策略 | 每个任务内重复设置所有技能 |
| 拾取后勤 | 二级页签：拾取、背包处理、补给恢复、异常恢复 | 登录密码、活动次数、临时脚本输出 |
| 登录角色 | 启动器路径、区服、账号引用、角色身份、登录步骤、绑定方式、断线策略 | 把登录凭据复制给其他角色 |

脚本版本、能力诊断、资源使用和完整日志放在底部抽屉/设置，不占用一级玩法导航。任务库主分类不等于游戏的日常标签：燕子坞可以带“日常”标签，但仍只有一个规范任务 ID。

## 3. 任务库的分类与统一模型

任务目录是版本化清单，来源状态和引擎适配状态分别显示：官方收录/限时公告/服务器待核对；已验证/待适配/不适用/需人工。只有“已验证且前置条件满足”可执行；其他条目可以做方案草稿，但不能显示为已经可运行。

目录首批覆盖：

- 副本：除匪首力破三关、楼兰寻宝、燕子坞、少室山、四绝庄、挑战缥缈峰、兵圣奇阵、琅嬛福地、王陵、三神幻境、观山海等官方收录项。
- 日常：师门、惩凶打图、漕运；帮会相关任务作为条件性条目，不同服型规则单独核对。
- 限时：珍珑棋局、贼兵入侵、偷袭门派、问道昆仑、寒山会武。竞技与帮会活动有目录入口但不默认加入自动队列。
- 生活：种植、钓鱼、采矿、采药，以及制作类扩展槽位。
- 野外：定点/路线刷怪、挖藏宝图、使用寻宝图、夺宝马贼。游戏图种类在物品识别层区分。
- 工具：已有的洛阳近距离移动、返回补给、背包处理检查点、等待时段、人工确认点。

这是“首批设计覆盖目录”，不是穷尽当前所有服务器内容。未确认的别名不强制映射：例如“老三环”等玩家俗称，要在游戏核验后添加 alias，不能只凭记忆填进执行参数。

每个任务有稳定 task_id、名称/别名、归属类别和多标签、产品/服型/版本、来源及核对日、有效期、角色/队伍/技能条件、依赖能力、参数 schema、可用执行方式、完成判据、资源消耗说明、可暂停阶段。不要把剩余次数未知显示成 0；显示“待读取/待确认”。

## 4. 参数按玩法差异显示

| 类型 | 默认显示参数 | 详情/高级参数 |
|---|---|---|
| 副本 | 难度、目标次数、完整通关/扫荡、队长或队员、战斗方案 | 组队等待、补员、关卡策略、退出条件、点数消耗与不足处理 |
| 师门/固定任务 | 目标轮次、接受的任务分支、物资来源 | 买入预算、缺物品时暂停/跳过、不接受任务分支的处理 |
| 漕运 | 路线、目标趟数、预算 | 官票/货物识别、遇敌或中断恢复 |
| 限时活动 | 目标场次、允许时段、截止策略 | 提前等待、队伍要求、安全检查点切入、过期处理 |
| 种植 | 作物与早/晚产类型、田地/坐标、轮数、播种/收获 | 占用等待、可选备用地、采集失败处理；禁用无间隔高频抢点 |
| 钓鱼 | 鱼群/地点、持续时间或目标数量、工具 | 鱼群耗尽换点、补工具、背包满处理 |
| 采矿/采药 | 资源种类、路线、数量或时长 | 技能门槛、工具、刷新等待、空点跳过、寻路失败 |
| 自动刷怪 | 地图/范围或路线、目标怪、持续时间、战斗方案 | 拉怪/脱战、追击上限、离开范围、死亡恢复 |
| 挖图/马贼 | 图种、数量；或目标场景、队伍/搜索范围 | 掉洞/遇怪分支、线索有效期、掉落处理 |

侧边详情的三个局部页签为“任务参数 / 前置与完成 / 规则覆盖”。只展示当前类型的字段；高级项默认折叠，始终保留单位、取值范围与继承来源。

## 5. 顺序队列与时间安排

首版以顺序列表为主，支持可访问的上下移按钮，拖动是补充。任务节点保存自己的参数快照，不直接引用任务库当前编辑表单。相同玩法的多个节点共享角色的日/周配额账本，不能重复计算可执行次数。

每个角色只能有一个前台角色动作执行器；战斗、寻路、交互、采集不得由多个脚本同时抢写。多个角色可以各运行自己的队列，但并发许可与游戏实际可启动数量分开显示；现阶段没有解除双开限制。

节点种类：运行任务、等待时段、补给/背包检查点、人工确认点。可设置失败后停止队列、跳过、有限重试或等待人工；默认停止队列，保留配置与现场记录。无限刷怪和无限采集不可放在队列中阻塞后续节点，必须设置时长、数量或明确结束条件。

限时任务选择：未开放时等待/先做可插入任务/跳过；结束前无法进入时跳过或暂停。只能在声明过的安全检查点插入活动，不在副本 BOSS 战、交付中途、播种提交期间强行切走。已种田等待成熟时可释放角色动作锁；观察任务记录田地和成熟待核对状态，不代表后台脚本可同时操控角色。

日/周重置以任务的服务器规则为准，不统一假定每天零点。过期活动节点显示失效并拒绝启动；运行时再次验证配额和活动状态，不能只在加入队列时检查。

开始前检查登录/角色身份、绑定、版本、能力、地图、配额、队伍、物资和规则冲突。默认队列含未适配节点时不启动，并列出原因；如要只运行支持项，需要用户显式禁用其余节点。

## 6. 配置继承、保存和修改生效

通用规则采用角色默认值 → 方案值 → 当前任务覆盖，覆盖项必须展示“已覆盖角色默认”；物品保护规则始终优先。模板变更不会悄悄修改已保存的独立角色方案，提供版本差异预览和显式更新。

区分草稿、已保存配置、正在执行的快照。修改时显示未保存标记；“保存草稿”不触发执行。执行中的参数在下一任务/安全检查点应用，当前关键动作完成后再切换。Lua 重载仍按候选校验、失败保留旧版、状态兼容和安全切换处理。

Home 绑定/选择当前游戏，不隐式开始；End 停止并解绑当前会话；Insert 显示/隐藏。游戏退出停止对应 Worker；角色方案和历史仍保留。重新连接后默认不自动续跑不可逆动作，先核对完成记录与游戏状态。

## 7. 批量复制：生成独立副本

流程：选择来源角色 → 选择目标角色 → 勾选范围 → 查看差异/冲突 → 应用。

可选范围：任务队列与参数、时间安排、战斗模板（同门派兼容时）、拾取规则、补给与恢复、生活采集配置。支持覆盖选中范围与仅填空；范围之外保持目标原值。

不复制：账号凭据、登录身份、大区/服务器、角色 ID、PID/窗口/进程 token、运行状态、历史完成次数与日周配额。不同门派不复制技能绑定；不同服务器重新验证玩法与地图。销毁规则可复制规则内容，但启用状态必须关闭并要求按目标角色的物品重新预览。复制源后续修改不影响目标角色。

运行中的目标角色只接收草稿，下次安全切换时应用，不立即干预其游戏。

## 8. 战斗、拾取与后勤

战斗技能按角色门派组织方案。技能项包含优先级、目标/范围、冷却与资源条件、生命阈值、仅首领/群怪/自保/治疗队友等条件。昆仑等形态机制作为条件维度，不固定把所有技能混在一张无条件循环表中。无法读取的技能明确显示待适配，不虚构冷却读数。

地面拾取：启停、拾取范围、物品类别/品质、名单、拾取归属与可拾状态、战斗中是否允许、包裹满时策略；具体归属机制以游戏能力核验。背包处理：保留、整理、存仓、出售、销毁分开动作，默认先保留。

销毁默认关闭。保护规则（任务必需、锁定/装备中、明确保留名单及未知属性）优先于销毁白名单；不得用模糊名称直接删除，也不能只因包满清空背包。先预览拟匹配项，显示数量、规则与保护原因，再显式启用；运行前仍重新核验对象身份。规则变动或复制到新角色后需要重新预览。原型仅演示匹配，不读取或销毁真实物品。

补给恢复统一设置生命/内力阈值、补给品、冷却、库存下限、购买/修理预算与满包策略。正在交互/采集中不同时派发冲突补给动作；允许的紧急恢复优先级由执行器统一仲裁。死亡、掉线、卡路、队伍不足各有有限重试与人工接管出口。

## 9. 登录流程设计

安装目录/启动器 → 选择产品和大区/服务器 → 账号认证 → 选择精确角色 → 等待进入世界 → 核对角色/地图 → 绑定角色配置 → 等待显式启动队列。

支持账号密码登录和需要人工完成的扫码/验证步骤作为不同分支，验证码或身份验证进入“等待人工”，不循环尝试绕过。凭据按本机系统凭据引用保存，不写进 Lua、方案导出或复制内容。原型没有真实密码输入，也不发起认证。

每一步显示成功判据、超时、有限重试和人工继续。断线重登是单独开关；重登成功不重复执行已经确认交付、消耗或销毁的步骤。登录到其他角色时保持未绑定，不把其接到原队列。

## 10. Qt 实现路径和性能约束

后续仍在现有 C++/Qt Widgets 工程内实现，不替换成浏览器壳。使用角色 QAbstractItemModel/QListView、任务/队列 QTableView、六主页面 QTabWidget/堆叠页、详情栏 QSplitter；大量任务使用模型视图和按需创建详情，不为所有玩法常驻创建控件或启动 Worker。

保留 Worker 隔离与已有资源限额；UI 默认只刷新当前可见角色，按事件更新并限频。隐藏面板不进行高频重排；日志有界且详细日志按需加载；菜单切换不创建游戏线程钩子。未开始的队列、未登录的配置不启动脚本进程。保留配置 schema 迁移、版本回退和当前发布版。

已核对现有实现：Worker 单进程提交内存上限 192 MiB、Worker Job 合计 512 MiB、CPU 硬上限 10%，UI 日志最多 1000 个文本块；游戏本身不纳入该 Worker Job。后续沿用这些保护并区分资源配额和实际占用。是否长期不卡顿必须通过真实多会话、隐藏面板、反复开始/停止、重载和游戏退出的持续采样验收，不能仅凭设计或现有短测试作保证。

设计原型不连接 C++、游戏、外部网络或真实登录系统；示例角色 A/B/C 不代表已经启动三个游戏。

## 11. 分阶段落地与验收

1. 界面骨架：角色独立配置、六 Tab、任务目录、详情表单、保存状态；既有真实移动完整保留。
2. 队列与复制：节点顺序/启停/参数快照、复制差异与排除、版本/能力预检。先用移动节点实机验证顺序，不能拿假副本报告成功。
3. 共用能力：物品/背包、战斗/技能、NPC/任务、跨图导航、补给等独立适配后逐项开放任务。
4. 生活与固定任务：种植、钓鱼、采矿、师门等分别验证结果确认，不按“目录已有”批量宣称完成。
5. 副本、活动、刷怪/宝图/马贼及登录：按玩法和服型逐项验收，再做长时间多会话性能验证。

关键交互验收：切换角色不串号；复制不带凭据或运行进度；不同门派复制不污染技能；销毁未经目标预览不启用；限时过期不启动；未适配节点不能执行；队列中无限任务有结束条件；人工接管后仅在明确策略下恢复；退出游戏只停止对应会话。
